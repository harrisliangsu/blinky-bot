# Bot 创建头像选择：给 Agent 的使用说明

## 目标

在创建 Bot 时，提供类似 Grok Bot 的头像选择：用户选择一个头像造型和一个颜色，在创建前看到预览，创建后在侧边栏、对话和 Bot 信息中看到同一个头像。头像应支持自然眨眼；AI 回复期间，眼睛平滑看向右侧。

这套素材以 Blinky 的 App 图标为母版：保留垂耳、五官、柔软材质和统一的视觉语言，用**头顶造型、脸型、颜色**区分不同 Bot。不要加入 CLI 符号，也不要把耳朵改成主要的区分元素。

`palette.json` 是 11 个建议配色的名称和 HEX 值；`palette.html` 可在浏览器中预览这些颜色。色值为设计参考，PNG 的实际颜色包含渐变、光照和阴影，并非像素级纯色。

**重要：现有 PNG 是静态合成图。**每个头像目前只有一种已画好的配色；眼睛、脸、耳朵和头顶都在同一图层中。文件没有提供 13 × 11 个现成颜色版本，也没有眼睛分层或动画文件。不能直接把一个色值存下来，就声称 PNG 已经换色或眼睛已经可以单独转动。

素材的画布尺寸不统一。部分透明边缘有少量杂点，`02-方糖.png`、`04-扁扁.png` 的外发光较明显。作为正式产品素材使用前，需检查实际背景和小尺寸效果，按需清理边缘并统一画布；不要直接拉伸变形。

## 创建界面

1. 展示 Bot 名称输入框、当前选中头像的大预览、13 个造型缩略图和 11 个颜色选项。
2. 点击造型或颜色时，更新选中状态和大预览；提供清晰的选中描边，并支持键盘操作、可读的无障碍名称。
3. 预览、选择列表、侧边栏和对话中使用同一个头像渲染组件及同一组数据，避免创建前后显示不一致。
4. 头像放在统一比例的容器中，保持原始宽高比并完整显示耳朵和头顶；不同素材的留白和视觉占比应在正式素材处理时统一。
5. 页面上的具体布局、交互和组件实现遵循现有产品设计与项目技术栈。不要依赖本机绝对路径运行 App；将所需文件放入项目现有的资源目录，使用项目的静态资源机制打包。

## 颜色实现

参考 Grok Bot 的交互，目标是**选择不同颜色后，头像本身真实变色**，不只是改变色块的选中状态。推荐把脸部可换色区域拆为独立遮罩或图层，在其上着色，并保留原有的明暗、渐变、腮红、眼睛、鼻子、嘴、耳朵和头顶材质；也可以为每个需要支持的造型与颜色提供预渲染素材。具体方案按项目渲染技术选择。

不要把整张 PNG 用单一 CSS `filter` 或纯色蒙版强行染色：这样容易污染眼睛、腮红和耳朵，破坏原图质感。生成或处理后的所有造型与颜色组合应与预览一致，在浅色和深色背景下检查效果。

在换色素材或渲染能力尚未完成时，可以使用原始 PNG 做静态造型预览；不要让用户选中某个颜色却仍显示另一种颜色，也不要把配色表中的 11 个 HEX 宣称为现成的 143 张头像文件。

## 眼睛动画

目标是眼睛自然运动，而不是整个头像平移：

- **待机**：偶尔自然眨眼；不需要多个 Bot 同步眨眼。
- **AI 回复中**：由实际的 Bot 回复状态驱动，两只眼睛平滑转向右侧；回复结束后平滑回正。允许继续自然眨眼。
- **减少动态效果**：遵循系统的减少动态效果设置，提供静态展示或关闭非必要动画。

由于当前眼睛已画在 PNG 中，实现前需要为每个使用的头像制作干净的无眼睛底图，以及左右眼等独立可动图层，或提供可控的分层动画资源。分层要与原画的光照和位置对齐，避免原眼睛残影、穿帮或出现两对眼睛。小尺寸下检查视线和眨眼仍可辨认；等待、报错和完成等状态是否需要其他动作，以现有产品行为为准。

目录外早期的 `family-motion-v3.html` 只是基于另一组造型的动作概念演示，不是这 13 张 PNG 的分层资源，也不能直接当成生产动画素材。

## 保存与兼容

在现有 Bot 数据结构中保存稳定的**造型 ID**和**颜色 ID**，例如：

```json
{
  "avatarShape": "heart",
  "avatarColor": "mint"
}
```

具体字段名与数据迁移方式以现有代码和存储合同为准。为 `palette.json` 中的每个颜色建立稳定 ID，不要把展示名称或数组下标当作长期标识。读取旧 Bot、未知 ID 或缺失资源时，使用项目认可的默认头像；编辑 Bot 时应回显已保存的选择。不要静默替换已有用户自定义头像。

## 完成时检查

- 13 个造型均可单独预览、选择和保存，创建后重新打开仍是同一个造型和颜色。
- 支持的颜色组合会真实改变头像的脸部颜色；颜色、选中状态和创建后的显示一致。
- 每个使用动态能力的头像都能自然眨眼；回复中向右看、结束后回正，且与真实回复状态一致。
- 检查缩略图、侧边栏及较大的预览，确保轮廓可辨、耳朵与头顶不裁切，浅色和深色背景下无明显透明边缘问题。
- 验证减少动态效果、键盘选择、旧数据回退，以及项目要求的相关检查。
