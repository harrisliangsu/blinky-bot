# 局域网远程重启恢复

只有用户通过 Mac 明确开启的新版共享，才会生成 `sharing-recovery.json`。
单独读取 rooms 列表不会启动监听；升级时旧 `enabled` 字段仍按关闭读取，不自动启用旧邀请。
恢复文件通过 Electron safeStorage 加密、owner-only 临时文件 + fsync + 原子替换保存。
不支持安全存储（包括 Linux basic_text）时仅保留临时共享，主机界面说明重启后需要重新开启。
不可解密或损坏的记录不会自动开启监听，也不会在启动时覆写。

记录绑定房间 id、会话 id、邀请 token、主机 Ed25519 身份及设备公钥、批准范围和原到期时间。
设备批准仍是八小时，不因重启延长。每个请求继续验证设备私钥签名；恢复时轮换 grant，
旧请求凭据不能重放。新设备和失去浏览器私钥的设备必须经主机明确批准。
撤销、拒绝和权限修改先同步保存再确认成功；保存失败不会假称成功。停止共享从恢复记录删除房间。
正常退出只暂停监听，保留恢复记录；明确停止和撤销不会在下次启动复活。

仅前台 App 启动阶段尝试恢复，不通过 Agent/native runtime 或例程后台唤醒启动 LAN 服务。
监听绑定原 LAN 地址和端口；暂时无网络时每 15 秒重试。原地址缺失或端口被占用时，
主机明确显示原因，不静默换到陌生地址/端口。回到原网络/释放端口可自动恢复。

地址改变需要从 Mac 提供新地址：旧网页无法在无可信发现服务的条件下发现新 IP；
浏览器身份与草稿又受 origin 隔离保护，新 origin 不应自动取得旧 origin 的私钥。
设备重新批准的具体条件为批准到期、设备身份丢失、明确停止后新邀请、主机身份无法解密，
或浏览器 origin 改变导致身份不再可用；普通同地址宿主重启不再要求重新批准。
不修改用户网络配置或绕过浏览器/系统保护来消除这些边界。

远程恢复时重建 watches 和历史游标，保留加载过的历史及阅读锚点，不自动重发消息。
同 origin/同邀请的当前标签页保留草稿；上传引用按设备 + 邀请绑定，安全存储可用时在一小时
有效期内跨宿主重启恢复。引用过期/文件不可读时明确要求重新选择，禁止读取任意主机路径。
撤销或范围改变清除旧页面与草稿。手动刷新不是自动重发，附件采用引用而不是在浏览器存储大幅预览。

测试分别记录实际挂载 Electron + Chromium 远程 UI、合成加密边界、单元测试和未验证的实体 iPhone/Safari。
实体手机键盘、真实 OS Keychain/通知授权、旧 macOS/其他 CPU 的结果不得从模拟能力推断。
